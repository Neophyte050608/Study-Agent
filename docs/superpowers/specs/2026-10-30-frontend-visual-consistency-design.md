# 前端轻量视觉统一设计

## 1. 已确认方向

采用 **Naive UI + 保留现有品牌色 + 轻量统一**，解决页面各自设计、基础控件重复手写的问题。继续使用 Vue 3 + Vite，不重做产品信息架构，不新增后端能力。

本设计承接用户对上述方向的确认；落地前由用户复核本文件中的范围和验收标准。

## 2. 现状与目标

当前页面已有语义色变量和深浅色切换，但没有组件库；页面标题、间距、圆角、按钮、表单和反馈状态各自实现。知识库存在重复标题，模型管理和聊天弹窗存在大量独立样式。仅统一颜色不能解决这些差异。

目标：

- 全站共享字体、品牌色、深浅色主题，以及标题、间距和控件层级。
- 按业务保留不同结构：聊天仍是聊天，画像仍保留图表，管理页采用清晰的信息面板。
- 基础控件直接使用 Naive UI，减少手写 CSS 和重复交互代码。
- 每个迁移页面同时删除被替代的模板与样式，不留下两套可切换实现。

非目标：修改路由、侧边栏功能归属、API、模型选择策略、聊天消息顺序、Markdown 解析、题卡提交或后端持久化；另行重构启动流程、安装其他 UI 库、全面迁移现有 Tailwind 布局。

## 3. 依赖与组件使用

只新增 `naive-ui`，通过显式命名导入使用的组件，不全量注册，也不新增自动导入插件、图标库或字体包。

已核对官方 npm 元数据：当前 Naive UI 2.45.3 的 Vue peer dependency 为 `^3.0.0`，与项目 Vue 3.5 兼容。实际安装结果由 lockfile 记录并通过构建验证。

优先替换：

| 职责 | 组件 |
| --- | --- |
| 操作与表单 | NButton、NForm、NFormItem、NInput、NInputNumber、NSelect、NSwitch |
| 面板与数据 | NCard、NDescriptions、NTable/NDataTable、NPagination、NStatistic |
| 分组与状态 | NTabs、NTag、NAlert、NEmpty、NSpin |
| 浮层与反馈 | NModal、NPopconfirm、NMessageProvider/useMessage、NDialogProvider/useDialog |
| 布局 | NFlex、NSpace、NGrid（仅在实际有用的位置） |

不要创建 BaseButton、AppButton、BaseInput 等转发库属性的包装组件。保留有业务职责的页面私有组件；只有出现两个真实消费者时才提取共享页面标题/面板组合。不提前创建空组件目录或通用设计框架。

## 4. 主题与视觉基线

### 4.1 一个主题状态与一份颜色定义

- `useTheme` 提供共享响应式主题状态，不再让应用根节点与侧边栏分别维护独立的 isDark。
- 保持 `localStorage.theme`、根节点 `.dark` 和首次使用系统偏好的既有行为。不新增第二个存储键或单独的组件库主题开关。
- 现有语义色值原样集中到一份主题定义，由其生成原有 CSS 变量和 Naive UI theme overrides。移除 `index.html` 中对应的重复颜色声明。
- 原有 Tailwind 语义工具类继续消费同一套 CSS 变量；组件库不默认使用另一套绿色主色。
- 根节点配置 NConfigProvider，中文 locale，并按共享状态选择 light/dark theme。消息与对话框 provider 继承同一主题。
- 第一阶段避免引入全站 CSS reset 或 NGlobalStyle，以免改变未迁移页面、Markdown 和代码块。现有布局和代码展示样式继续有效。

### 4.2 统一但不抹平业务结构

- 保留当前靛蓝品牌色，沿用现有字体资源；正文使用 Inter 与中文系统字体回退，代码保持等宽字体。
- 普通页面只保留一个主标题：24px、600 字重；描述使用 14px 次级文字。面板标题使用组件库默认层级，不为每页设计新的字号组合。
- 常规页面内边距：桌面 24px，窄屏 16px；主要区块间距 24px，区块内操作间距 12–16px。
- 基础控件圆角统一为 8px，卡片为 12px，常规控件采用组件库 medium 尺寸。
- 主操作使用 primary，次要操作使用 default/tertiary，删除等危险操作使用 error 与确认交互。不靠额外渐变、夸张阴影或动画突出普通操作。
- loading、error、empty 分别表达；失败不能显示为健康或成功，未知数据不制造正常指标。
- 以上基线仅约束本次迁移页面。不会仅为匹配字号而改动聊天气泡、图表尺寸或题卡布局。

## 5. 分阶段迁移与完成条件

### 第一阶段：主题接入 + 模型与路由完整样板

范围：应用根节点、共享主题、模型页及其候选模型和路由健康局部组件；同步前端开发规范与验证说明。

- 统一模型页标题和操作区，替换候选列表、编辑表单、弹窗、状态标签和反馈控件。
- 保留 `useModelsAdmin`、modelPresentation 和现有 API contract，不把业务编排塞入 UI 组件。
- 保持 API Key 的“不填写保留、填写替换、显式清空”语义；密码输入不得预填掩码或泄漏已有密钥。
- 路由健康保留实际快照、状态与错误信息；不新增模拟进度、伪造统计或不接事件的装饰按钮。原有装饰区域不作为迁移后必须保留的业务功能。
- 数据加载、刷新失败、候选为空和保存失败都有可见状态，防止重复提交。
- 改造整个模型页的基础控件，不只替换最上方一个按钮就宣称该页统一完成。
- 不修改当前已有未提交改动的聊天相关文件。

完成后先查看实际页面效果，再将样板用于后续页面，不一次性全站改动。

### 第二阶段：知识库、画像及其他管理页面

- 知识库去掉重复主标题，统一上传、筛选、列表、状态反馈与删除确认。
- 能力画像统一页面标题、操作、卡片和表单；保留 Chart.js 雷达图与学习计划流程。
- RAG、trace 详情和 Agent 管理采用同一套基础控件与标题层级，保留各自展示 contract 和数据加载边界。
- 有真实复用时再提取共享标题或内容组合；避免把不同页面硬塞成一张万能管理页。
- 不恢复已经删除的旧入口，不调整当前四项主导航及管理嵌套路由。

### 第三阶段：聊天交互控件收口

- 迁移会话操作、确认弹窗、提示消息和适合使用组件库的选择/输入控件。
- 对齐题卡操作按钮与状态样式；保留题卡业务结构。
- 保持聊天布局、消息排序、流式更新、Markdown、代码块和练习提交逻辑。
- 当前聊天文件已有未提交变更：执行此阶段前重新检查 diff，基于已有工作修改，不覆盖或顺带提交无关内容。

每阶段结束时，已迁移区域不再保留被替代的自制基础控件及其专属 CSS。不同阶段之间允许尚未迁移的页面保持原样，但不新增旧式控件实现，也不提供新旧 UI 切换机制。

## 6. 验证与验收

### 自动验证

沿用 Node 内置测试运行器，不另装测试框架：

```bash
cd frontend
npm test
npm run build
```

第一阶段补充主题颜色映射、深浅色共享状态和初始化/持久化行为测试；模型管理继续验证 key 更新语义、展示数据和操作 contract。源码契约测试按新组件结构调整，不将源码断言当成浏览器交互覆盖。

### 浏览器检查

使用可用浏览器工具和隔离 mock 数据，分别标注 mock 验证与真实后端联调：

- 在 1440px 和 390px 视口查看模型页，内容不覆盖侧栏，操作区可换行，表格可横向滚动但页面不发生不可控横向溢出。
- 深浅色切换同时作用于旧页面、组件库控件和浮层；刷新保留选择。
- 创建/编辑模型、取消弹窗、保存失败与重试、key 保留/替换/清空、删除确认按原 contract 工作。
- 表单标签可关联输入，键盘可进入控件和浮层，关闭浮层后焦点恢复；危险操作不能误触直接执行。
- 检查聊天与画像等未迁移页面，确认主题接入没有破坏原有布局、Markdown 和图表。
- 记录构建体积和浏览器错误，避免全量组件注册导致无意义膨胀；不承诺改造后包体一定变小。
