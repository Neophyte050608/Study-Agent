# 现有聊天体验收口设计

## 1. 背景与目标

项目已经把面试和算法练习并入 AI 助手消息流，但导航、路由和默认菜单仍保留旧入口；聊天历史还存在同一秒消息排序不稳定、回答内容与操作区层次不清等问题。

本阶段暂停扩展新的 Agent 能力，先让现有功能形成一个稳定、清晰、可持续维护的产品入口。目标如下：

1. `/chat` 成为对话、面试和算法练习的唯一入口。
2. 删除未上线产品不需要的旧菜单与旧路由，不保留兼容跳转。
3. 消息在首次发送、流式完成和重新加载后始终保持用户发言在前、对应回答在后。
4. 回答正文、结构化卡片、技术执行信息和操作按钮互不遮挡。
5. 保留 `route`、`via`、`mode`、`local graph`、`rag`、`fallback` 等技术信息并直接展示。

## 2. 范围

### 2.1 本次包含

- 清理“面试控制台”和“算法刷题”菜单。
- 删除 `/interview`、`/coding`、`/practice` 及相应 `.html` 前端路由。
- 删除前端路径转换和兜底菜单中的旧入口。
- 从后端默认菜单中删除 `DASHBOARD` 和 `CODING`。
- 新增 Flyway 迁移，删除现有数据库中的 `DASHBOARD` 和 `CODING` 菜单记录，并调整保留菜单的排序。
- 固化聊天消息的稳定时序契约。
- 调整聊天消息卡片、技术信息区、操作区、消息滚动区和输入区布局。
- 为菜单清理、消息时序和前端消息规范化补充回归验证。

### 2.2 本次不包含

- 不删除面试、刷题的业务能力和聊天内结构化卡片。
- 不新增聊天模式页、兼容页或跳转提示页。
- 不隐藏或折叠技术执行信息。
- 不改造 Agent 路由、RAG 算法、模型选择或流式协议。
- 不做整套视觉品牌重设计，也不引入新的 UI 或测试框架。
- 不顺带重构与本问题无关的 `ChatView.vue` 逻辑。

## 3. 信息架构收口

### 3.1 唯一入口

`/chat` 保留为 AI 助手唯一入口。面试和算法练习继续由对话意图识别、快捷操作或结构化卡片触发，不再表现为平级应用。

旧路由从路由表中直接删除：

- `/interview`
- `/interview.html`
- `/coding`
- `/coding.html`
- `/practice`
- `/practice.html`

项目尚未上线且只有本地用户，不为这些路径保留重定向、兼容层或迁移提示。访问不存在的旧地址时，沿用现有未知路由处理，不赋予它们任何特殊行为。

### 3.2 菜单真相源

旧入口必须从所有权威来源一起消失，避免接口失败、缓存刷新或重新建库后重新出现：

- `MenuConfigService` 默认菜单不再创建 `DASHBOARD`、`CODING`。
- 前端 `AppShell.vue` 的兜底菜单不再包含这两个菜单。
- `AppShell.vue` 的 `toSpaPath` 不再识别旧路径。
- Flyway 新迁移删除已有 `t_menu_config` 中的 `DASHBOARD`、`CODING` 记录。
- 新迁移统一保留菜单的 `sort_order`，使 AI 助手位于主要功能入口首位。

既有 Flyway 迁移保持不可变；不回改已经执行过的 `V2__seed_reference_data.sql`。新数据库会先执行历史种子，再由新迁移收敛到最终状态。

`MenuConfigService.normalizeUrl` 对空路径的默认值改为 `/chat`，并删除对旧面试、刷题路径的归一化。菜单配置若仍被手工写成旧地址，不再由应用暗中映射到聊天页。

## 4. 消息时序契约

### 4.1 统一规则

聊天消息 API 对每一页都返回从旧到新的稳定顺序：

```text
created_at ASC, id ASC
```

`created_at` 表达时间，数据库自增 `id` 作为同一时间精度下的稳定决胜字段。不能只按秒级 `created_at` 排序，也不能依赖数据库未声明的自然顺序。

页面大小仍限制为最多 200 条。无游标时返回最近一页，而不是会话最早的一页；使用 `beforeId` 时返回该消息之前最近的一页。后端可以先按倒序取最近 N 条，再在应用层恢复为升序，但公开响应始终遵守“旧到新”的契约。

### 4.2 前端规范化

前端把消息转换、稳定排序和必要的去重收敛为一个可测试的纯函数，而不是让模板或多个刷新分支分别处理：

- 使用持久化 `messageId` 去重。
- 对缺少 `messageId` 的本地临时消息保留当前数组顺序，不用正文内容推断身份。
- 持久化消息按 `createdAt`、`id` 排序。
- 同一响应中的结构化卡片和普通文本服从同一时序规则。
- 静默刷新以服务端持久化结果为准，不把已经持久化的乐观消息再次追加一份。

发送过程保持以下可见顺序：

```text
用户消息（立即显示）
AI 流式回答
AI 最终回答（持久化刷新后位置不变）
```

流式完成后仍可刷新持久化数据，但刷新不能反转消息或制造重复项。

## 5. 聊天页面布局

### 5.1 消息卡片结构

助手消息采用正常文档流，不使用会覆盖正文的绝对定位。每条消息按固定顺序渲染：

```text
助手头像 + 消息容器
  ├─ 回答正文
  ├─ 图片或结构化卡片
  ├─ 技术执行信息区
  └─ 操作区（点赞 / 点踩 / 复制）
```

具体约束：

- 回答正文允许长文本、代码块和图片自然增高；超宽代码块在自身区域横向滚动，不撑破消息容器。
- 技术执行信息紧跟正文或卡片，以独立区域直接展示。
- 操作区位于卡片底部，使用上边距和顶部边线与内容分隔；按钮可以换行，但不能覆盖正文。
- 用户消息保持右对齐，助手消息保持左对齐，角色层次不改变。
- 消息循环使用稳定键：优先 `messageId`，本地临时消息使用显式临时键，不继续以数组下标作为唯一身份。

### 5.2 技术信息

当前用户就是产品使用者，以下信息继续默认可见，不放入折叠面板：

- 生成状态
- `mode`
- `local graph`
- `rag`
- `fallback`
- `route`
- `via`

它们集中放在“技术执行信息区”，保持紧凑标签样式。失败和降级仍通过颜色区分，但不改变字段含义，也不新增后端数据。

### 5.3 滚动与输入区

消息列表和输入区保持两个正常布局区域，输入区不悬浮覆盖消息：

- 消息列表独立滚动，并预留稳定底部空间。
- 输入区固定在聊天列底部的正常 flex 布局中，不使用覆盖消息的定位。
- 用户处于消息底部附近时，新消息和流式增量自动跟随到底部。
- 用户主动上滚阅读历史后，流式更新不强制把视口拉回底部。
- 用户发送新消息时，无论此前位置如何，都滚动到新消息处。
- 会话切换或首次加载完成后滚动到最新消息。

检索模式选择器继续显示；本次只调整其与输入框的间距和容器关系，不改变选项或请求参数。

## 6. 代码边界

本次采用针对性收口，不做全面组件重构：

- `AppShell.vue` 负责前端导航显示和路径转换。
- `MenuConfigService` 与 Flyway 负责菜单最终状态。
- `WebChatService` 负责 API 的分页与稳定时序契约。
- 新增前端纯函数模块，负责聊天响应的解析、排序和去重，供 `ChatView.vue` 调用并由 Node 测试覆盖。
- `ChatView.vue` 保留会话和流式编排，只调整消息结构、滚动策略和稳定键。

不会为了这次改动创建空 facade、临时 adapter 或只转发调用的过渡组件。若模板调整后仍能保持清晰，就不额外拆分消息组件；只有当同一块标记被历史消息和流式消息重复使用且会产生行为分叉时，才提取一个有实际职责的展示组件。

## 7. 数据迁移与错误处理

Flyway 迁移仅处理菜单配置：

1. 删除 `menu_code IN ('DASHBOARD', 'CODING')`。
2. 更新保留入口的顺序。

迁移不删除面试或刷题业务表，不删除历史聊天数据。菜单缓存由应用现有失效/重启机制重新加载；本地开发迁移后重启应用即可得到最终状态。

聊天消息加载失败时保留当前可见消息并显示现有错误提示，不清空用户刚看到的内容。流式失败和主动停止继续沿用现有状态语义，本阶段只保证失败消息位置正确、操作区不遮挡。

## 8. 验证标准

### 8.1 自动验证

- 后端菜单测试证明默认菜单不含 `DASHBOARD`、`CODING`，空 URL 归一化为 `/chat`。
- Flyway 迁移脚本检查证明删除旧菜单且不修改面试、刷题业务数据。
- `WebChatService` 测试覆盖同一 `createdAt` 下按 `id` 稳定排序，以及“最近 N 条、响应升序”的分页语义。
- 前端 Node 测试覆盖消息解析、同秒排序、去重和结构化消息顺序。
- 运行前端测试与构建；运行后端相关测试，架构边界未改变时不扩张无关测试范围。

### 8.2 页面验收

使用实际本地页面至少验证：

1. 侧栏只有一个 AI 助手入口，不出现面试控制台和算法刷题。
2. 旧 URL 不再跳到 `/chat`。
3. 连续发送多轮消息后，用户消息始终位于对应回答之前；刷新页面顺序不变。
4. 长 Markdown、代码块、图片和面试/刷题卡片不会与操作按钮重叠。
5. `route`、`via`、`mode`、`local graph`、`rag`、`fallback` 在有值时直接可见。
6. 位于底部时流式回答自动跟随；上滚阅读时不会被反复拉到底部。
7. 输入区不覆盖最后一条消息，窄窗口下标签和按钮可换行。

## 9. 完成定义

同时满足以下条件后，本阶段才算完成：

- 旧菜单、旧路由、旧路径转换和数据库旧菜单均已删除。
- 面试与刷题仍可在 AI 助手消息流内使用。
- 消息时序在发送、流式完成、静默刷新和页面刷新后保持稳定。
- 正文、技术信息与操作区结构分离且无重叠。
- 自动检查和本地页面验收均通过。
- 没有引入兼容层、临时入口或无职责抽象。
