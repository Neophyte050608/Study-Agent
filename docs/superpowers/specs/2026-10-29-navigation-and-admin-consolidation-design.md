# 导航与管理中心收口设计

## 1. 背景

当前侧边栏把日常学习功能、模型运维、RAG 观测、Agent 调试和动态菜单编辑平铺在同一级：

- AI 助手、知识库管理、能力画像属于日常产品入口。
- 系统监控、模型管理、运维中心、RAG 监控属于后台运行治理。
- MCP 工具台、意图树配置、提示词管理属于 Agent 专家配置。
- 面试控制台、算法刷题已被聊天内能力替代，但旧 Redis 菜单缓存仍会把它们重新暴露。
- 模型配置页面读取 `/api/settings/agents`，当前返回空配置；其持久化配置没有被 Agent 运行时读取，是断链空壳。
- 扩展空间允许再次修改菜单布局，使 Flyway、数据库、Redis、后端默认菜单和前端兜底菜单共同成为菜单真相源。

本次目标不是隐藏若干菜单，而是删除失效设计、合并重复能力，并建立单一、稳定的信息架构。

## 2. 目标与原则

### 2.1 目标

一级侧边栏只保留四项：

1. AI 助手
2. 知识库
3. 能力画像
4. 管理中心

管理中心按任务域分为：

1. 模型与路由
2. RAG 运行与评测
3. Agent 工具与配置

### 2.2 原则

- 不保留未上线产品不需要的旧路由重定向或兼容页。
- 不用“先隐藏、以后再删”的过渡状态；确认无运行时价值的代码本次直接删除。
- 不在新管理页面中简单嵌套整张旧页面；共享能力下沉为有职责的局部组件，然后删除旧页面。
- 不让菜单继续依赖 Redis、数据库布局或前端兜底列表，固定产品导航只有一个源码真相源。
- 不删除聊天内的面试、算法练习、结构化题卡等业务能力。
- 不把 API Key 作为普通配置明文回传前端。

## 3. 最终信息架构

```text
青梧
├── AI 助手              /chat
├── 知识库               /notes
├── 能力画像             /profile
└── 管理中心
    ├── 模型与路由        /admin/models
    ├── RAG 运行与评测    /admin/rag
    └── Agent 工具与配置
        ├── 提示词        /admin/agents/prompts
        ├── 意图路由      /admin/agents/intents
        └── MCP 能力      /admin/agents/mcp
```

管理中心使用页面内二级导航。一级侧边栏在所有 `/admin/**` 路由下统一高亮“管理中心”，不把管理子功能重新铺回主导航。

`/admin` 作为管理中心内部默认入口，固定跳到 `/admin/models`；这属于当前产品内部默认路由，不是旧 URL 兼容层。

## 4. 删除范围

### 4.1 删除旧产品入口

彻底删除：

- 面试控制台菜单及 `/interview` 入口。
- 算法刷题菜单及 `/coding`、`/practice` 入口。

面试和刷题的后端业务、Chat Agent 路由和聊天内卡片继续保留。

### 4.2 删除断链模型配置

删除：

- `/settings` 路由和 `SettingsView.vue`。
- `/api/settings/agents` 管理接口。
- 仅服务于该接口的 `AgentConfigService`、MyBatis DO 和 Mapper。
- `t_agent_config` 中不被真实运行时消费的配置数据和相应缓存。

若 `AgentConfig` 值对象仍被模型路由内部的已验证代码使用，则保留值对象并迁移到模型路由所有权下；不能仅因名称相同而误删有效模型解析代码。

真正的模型候选、健康探测、路由与熔断继续由 `modelrouting` 模块负责，并收口到“模型与路由”。

### 4.3 删除动态菜单系统

固定导航不再通过 `/api/settings/menu` 加载。删除：

- 菜单查询和布局更新 API。
- `MenuConfigService`、菜单持久化 Mapper/DO 和 Redis 菜单缓存。
- `WorkspaceView.vue` 和“扩展空间”。
- 前端 API 失败后的另一份兜底菜单。
- `t_menu_config` 的运行时用途。

使用新的 Flyway 迁移删除不再使用的菜单配置表和断链 Agent 配置表；不修改已经执行过的历史迁移。

主导航固定定义在 `frontend/src/shell/navigation.js`，由 `AppShell.vue` 单向消费。它只描述四个稳定产品入口，不承载可编辑布局能力。

### 4.4 删除被合并的旧页面路由

完成迁移后直接删除以下旧路由，不做重定向：

- `/monitoring`
- `/model-providers`
- `/ops`
- `/rag-dashboard`
- `/mcp`
- `/intent-tree`
- `/intent-list`
- `/prompts`
- `/workspace`
- `/settings`
- 相应 `.html` alias

Trace 详情和意图编辑迁移到新路由：

- `/admin/rag/traces/:traceId`
- `/admin/agents/intents/:index/edit`

## 5. 管理中心合并设计

### 5.1 管理中心壳层

新增管理中心布局，职责仅限：

- 管理中心统一标题和说明。
- 三个管理域的二级导航。
- 渲染当前子路由。
- 在窄屏下将二级导航转换为可横向滚动的标签栏或紧凑选择器。

它不读取模型、RAG 或 Agent 业务数据，也不成为新的巨型编排组件。

### 5.2 模型与路由

来源：`MonitoringView.vue` + `ModelProvidersView.vue`。

保留并重组：

- 候选模型列表、创建、编辑、启停。
- 连通性与健康探测。
- 模型路由统计。
- 熔断、失败和降级状态。

删除重复展示：

- 两个旧页面重复的模型状态摘要。
- 与候选模型运行无关的空配置卡片。
- 不能触发真实运行时变化的 Provider/模型名表单。

最终只有一个“模型与路由”页面。旧两个页面中的独立数据区可拆成局部组件，但旧页面组件本身在迁移完成后删除。

### 5.3 RAG 运行与评测

来源：`OpsView.vue` + `RagDashboardView.vue`。

按操作任务划分页面区域：

1. 运行概览：关键指标、降级状态、最近活动。
2. Trace：筛选、列表、详情入口。
3. 质量与评测：检索指标、评测数据集和运行记录。
4. 审计与幂等：运维审计、失败与恢复信息。

当前 `OpsView.vue` 体量较大，迁移时按这些真实职责拆成局部组件和 composable，不把两张旧页面模板直接拼成更大的单文件组件。`RagDashboardView.vue` 中与概览重复的数据只保留一个展示 owner。

### 5.4 Agent 工具与配置

来源：`PromptsView.vue`、`IntentTreeView.vue`、`IntentListView.vue`、`IntentEditView.vue`、`McpView.vue`。

三个子页继续保留独立路由和状态：

- 提示词：模板浏览、编辑、预览和缓存刷新。
- 意图路由：树配置、规则列表和规则编辑。
- MCP 能力：能力查看和受控调用。

它们共享管理中心壳层和 Agent 域内三级导航，但不强行合并成一个同时加载全部数据的大页面。原页面迁移为域内页面/组件后，删除旧顶层入口。

## 6. 数据、缓存与配置真相源

### 6.1 菜单

最终只有前端静态导航定义是菜单真相源。原因：

- 当前产品只有一个本地使用者，没有运行时菜单定制需求。
- 四个一级入口属于产品结构，不是运行数据。
- 去掉数据库和 Redis 后，部署迁移不会再被旧缓存覆盖。

### 6.2 模型

运行时模型配置的真相源保持在现有 `modelrouting` 模块：

- 候选模型与端点。
- 健康探测和熔断状态。
- 路由选择与统计。

删除旧 Agent 配置后，不新增第二套 Provider/模型名/温度配置。未来若确实需要按 Agent 选择模型，应建立到 `modelrouting` 的正式引用契约，而不是恢复断链表。

### 6.3 敏感信息

- API Key 不在列表和详情响应中返回明文。
- 页面只展示“已配置/未配置”或掩码状态。
- 更新时空值代表“不修改已有密钥”，显式清除使用独立动作或明确字段。
- 本轮不把密钥写入 Git、前端静态配置或日志。

## 7. 前后端边界

- 主导航由前端壳层拥有，不再通过后端菜单 API 驱动。
- 管理子页面继续使用现有业务 API，不为了页面合并创建只转发请求的新后端 facade。
- 如果旧页面发现重复 API，先确认响应职责，再合并契约；不以页面改版为由跨模块直连 Mapper 或基础设施实现。
- 模型运行能力仍归 `modelrouting`，RAG trace/指标归 `observability` 与现有知识评测契约，提示词/意图/MCP 归各自既有模块。

## 8. 实施顺序

### M1：四项导航与管理中心原子落地

以下变更作为同一个可运行里程碑提交，避免“管理中心”短暂成为空入口：

- 创建管理中心壳层、二级导航和正式 `/admin/**` 路由。
- 将当前仍有效的模型、RAG、提示词、意图和 MCP 页面能力迁入新路由；迁移采用文件归属调整和真实子页面，不创建包裹整张旧页面的临时 facade。
- 前端切换为四项静态主导航，并更新内部链接和活动态判断。
- 删除动态菜单读取、前端兜底菜单、Redis 菜单缓存以及旧管理路由。
- 删除面试控制台、算法刷题、模型配置、扩展空间入口。
- 新增数据库清理迁移。
- 重启后验证 Redis 中即使存在旧值也不能影响导航。

M1 完成时，四个一级入口都必须可用，所有 `/admin/**` 子入口可到达；旧 URL 不保留重定向。内容去重可以在后续里程碑继续，但导航和路由不允许新旧两套并存。

### M2：模型与路由去重合并

- 以候选模型管理和真实 modelrouting API 为主线，合并模型状态、探测、启停、路由统计和熔断信息。
- 删除重复摘要与不能改变运行时的配置控件。
- 完成后删除原系统监控和模型管理页面残留组件，不留下不可达旧实现。

### M3：RAG 运行与评测去重合并

- 拆分并重组 RAG 概览、Trace、评测和审计。
- 明确每项指标和运行记录的唯一展示 owner，删除重复面板和重复请求。
- 完成后删除原运维中心和 RAG 监控页面残留组件，不留下不可达旧实现。

### M4：Agent 专家配置整理

- 统一提示词、意图路由和 MCP 子页的页面标题、导航归属和错误态。
- 去除迁移后重复的外壳、样式和 API 调用，不把三个业务状态强行合成一个状态容器。
- 验证意图编辑等深层链接只使用新的管理中心路径。

### M5：死代码与文档清理

- 删除不再使用的菜单、Agent 配置前后端代码。
- 删除旧 API wrapper、样式和测试资产。
- 更新前端开发文档、启动/验收说明和架构入口说明。
- 运行全量相关验证并进行浏览器验收。

每个里程碑结束时删除该阶段替代掉的旧实现，不把兼容层留到未来清理。

## 9. 测试与验收

### 9.1 自动验证

- 前端导航测试精确断言四个一级入口及其路径。
- 路由测试证明新管理路由存在、旧路由不存在。
- 菜单 API/缓存相关测试随功能删除而删除；数据库迁移测试验证废弃表被清理。
- 模型与路由页面测试覆盖候选模型、探测、启停和错误态映射。
- RAG 管理测试覆盖概览、Trace 筛选、评测和审计的展示映射。
- Agent 管理测试覆盖提示词、意图和 MCP 的路由归属。
- 运行 `npm test`、`npm run build`、后端相关测试和 `ArchitectureRulesTest`。

### 9.2 浏览器验收

1. 侧边栏始终只有 AI 助手、知识库、能力画像、管理中心。
2. Redis 中的历史菜单缓存不能使旧入口重新出现。
3. `/interview`、`/coding` 和所有旧管理 URL 不具有特殊兼容行为。
4. 管理中心三个域之间切换时主侧栏保持管理中心高亮。
5. 模型候选、探测、启停和路由统计均可实际操作或查看。
6. RAG 概览、Trace、评测、审计无重复面板，详情链接可达。
7. 提示词、意图、MCP 功能可从 Agent 工具与配置到达。
8. 页面加载失败时显示明确错误态，不以空白页面伪装“配置已加载”。

## 10. 完成定义

- 一级导航只有四项且只有一个源码真相源。
- 面试与刷题只作为 AI 助手内能力存在。
- 动态菜单、扩展空间和断链模型配置已经删除，而非隐藏。
- 管理能力按模型、RAG、Agent 三域收口，旧页面和旧路由已经删除。
- 真实运行时模型配置仍只有 `modelrouting` 一套。
- API Key 不通过普通读取接口明文返回。
- 自动检查和浏览器验收通过。
- 没有新增临时 facade、兼容跳转、双写或待清理的过渡导航。
